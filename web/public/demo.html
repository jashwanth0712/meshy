Meshy is a decentralized, agent-friendly mesh VPN. Organisations connect devices, services and AI agents on one mesh, and every permission is an ENS name: claude-1.db1.prod.acme.eth is a one-hour, folder-scoped, revocable grant for one agent on one machine. The mark is an M drawn as a network: the solid node is your device, the rings are the devices you link, and the spark is the agent, deliberately held apart by a gap because it only reaches what it is granted.

The gap we're filling. Teams are wiring AI agents into real infrastructure with shared SSH keys, long-lived tokens or the human's own session: the agent has no identity of its own, nobody is accountable for it, and access never ends on its own. The tools that exist each cover part of the job. Mesh VPNs connect devices and users at the IP and port level, and one coordination server holds every rule. Bastions and PAM tools record and can end sessions, but they're built around humans and the operator owns the recordings. Local agent sandboxes confine files but don't reach remote machines or have a control plane. None of them combines a mesh, a real agent identity, folder-level scope, killing a live session on revoke, an audit the admins can't edit, and no single operator. One concrete finding from building Meshy: in NetBird, removing a peer does not reset its open TCP connections, so revoking access in the mesh doesn't actually stop a running agent. meshyd has to kill sessions itself. The matrix shows typical capabilities by category, not any one product.

Meshy is AGPL-3.0. New code: meshy/, meshnet/, contracts/, web/, menubar/, agent/, deploy/, e2e/.

The open-source stack, by layer. Transport: NetBird v0.82, used as a library. Its client/embed package (BSD-3) gives us a userspace WireGuard peer with no TUN device and no root, in the separate meshnet module, because NetBird and go-ethereum need incompatible pion/stun versions. Its management, signal and relay servers (AGPL) run on the provider next to our meshy-sync. Control and chain: the ENSv2 contracts on Sepolia (UserRegistry, PermissionedResolver, VerifiableFactory, UniversalResolver and UniversalHelper, plus Enhanced Access Control); go-ethereum with abigen-style bindings in Go, because there's no ENSv2 write SDK for Go; viem with Multicall3 batching in the dashboard; Foundry for the contracts and anvil to fork Sepolia for end-to-end tests. Enforcement: gliderlabs/ssh for our own SSH server (NetBird's has no auth or command-wrap hooks), golang.org/x/crypto for SSH, XChaCha20-Poly1305 and HKDF, go-fuse v2 for GateFS, bubblewrap on Linux, and Seatbelt plus eslogger on macOS. Proof and identity: Arkiv on the Rabdi testnet, written with raw transactions because there's no Go SDK, and World ID Agent Pass via the OIDC device flow. Surfaces: Next.js 16 and React 19 for the dashboard, @noble for byte-compatible policy sealing in the browser, fflate for audit chunks, fyne systray for the macOS menu bar app, and the Model Context Protocol for the Claude Code plugin.

Daemons, providers, the dashboard and the contracts all read the same names. Nobody has to trust anyone’s server.

Why this can't be built without ENS. The moment providers are decentralized, no provider can hold the access rules, because the org would have to trust whoever runs its tunnels. So the rules need a neutral home that the resource daemon, the provider, the dashboard and the slashing contract all read the same way. ENSv2 is exactly that, and its specific features carry the product. Native expiry is the grant lifetime, with no cron job. unregister() is revoke, and every meshyd sees it on the next block through UniversalHelper.findExactOwner. Enhanced Access Control gives a delegated admin root roles on one network's registries and a setter role for only the meshy.policy key. Each agent is a namespace, claude-1.agents.acme.eth, with its own PermissionedResolver where it may rotate only its SSH key and can't forge its World ID record. The device's SSH host key is pinned in meshy.ssh-host, so the CLI never trusts on first use. Resolver records survive unregister, so every policy is bound to the grant's token id and a re-registered name can't revive old rules. And ProviderRegistry.slash() checks an attestation against ENSv2 on-chain, which is only possible because the names live on the same chain. A DNS zone has none of these ownership, expiry or on-chain semantics; a central ACL database puts the trust back in one operator.

Why this can't be built without crypto. Stake and slash: providers deposit at least 0.01 ETH in ProviderRegistry and sign EIP-712 admission attestations; if one admits a peer to a name that was already dead, anyone can submit the attestation, the contract checks ENSv2 on-chain, and the reporter gets half the stake. That's what lets strangers run an org's tunnels. Seats in USDC: MeshySubscription pulls USDC per seat, sends 5% to the treasury, escrows the rest for the provider, and refunds unused months on cancel, with no invoices or payment accounts between org and provider. Sealed policy: the chain is public, so meshy.policy is a multi-recipient envelope (X25519, HKDF-SHA256, XChaCha20-Poly1305) readable only by the device and the org, and the dashboard seals it in the browser byte-for-byte compatible with the Go code. Append-only audit: Arkiv entities are created read-only, written by the device's own key, and trusted only when $owner matches the device's ENS addr. A shared clock: expiry and revocation are decided by block state, so every daemon agrees, and meshyd fails closed if its view of the chain goes stale. Proof of human: the provider validates a World ID Agent Pass ID token server-side and signs an attestation bound to the agent's address and an opaque per-org hash of the human; no World ID token or personal data goes on-chain. Honest status: the demo agent's attestation is currently a dev signature until World sandbox credentials are set up, and provider admission attestations are not yet produced by meshy-sync, so a real slash hasn't been demoed.

meshy

Which secrets? The agent connects to db1.prod.acme.eth by name: no IP address, no VPN config, no shared key or password passed around a team. Everything it needs to connect is public on ENS. The device's SSH host key is pinned in its meshy.ssh-host record, so the CLI never trusts on first use; its X25519 key in meshy.enckey is what grant policies are sealed to; its addr record is the only writer whose audit counts on Arkiv. The agent's own public SSH key sits in meshy.ssh on the agent's own resolver, so it can rotate it without anyone's help. The private halves never leave the machines that own them. The only private thing on-chain is the folder policy, and that is sealed to the device and the org. Today the command is meshy ssh, which resolves the name and pins the host key; plain ssh through mesh DNS is on the roadmap.

meshy

Every move, on the record. Each session start, file-op chunk, block and revocation is written to Arkiv by the device's own key, as a read-only entity sealed to the org key. Nobody, including the org's own admins, can edit or delete it, and anyone can run the same query the dashboard runs and see the same records, filtered to writers whose address matches the device's ENS record.
